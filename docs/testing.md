## Проверка интерфейса без API

```sh
AIAC_LLM_MODE=demo .venv/bin/python -m uvicorn aiac.web.app:app --reload --host 127.0.0.1
```

Если пользовательский сервер уже запущен, не останавливать его: использовать текущий
для чтения или отдельный localhost-порт для своей проверки. Не занимать 0.0.0.0.

1. `/health` возвращает `{"status":"ok"}`; главная показывает семь блоков недель,
   пять дней в каждом, имя и название. Футера нет. Проверить узкий экран.
2. День 1: форма отправляется без навигации, видны ответ и раскрываемая отладка.
   В demo текст честно сообщает, что API не вызывался; это только проверка интерфейса.
3. День 2: видны поля, лимит 64, три повтора, выбор варианта, счётчик будущих вызовов.
   Технические отчёты из Markdown на странице отсутствуют.
4. В demo запуск серии дня 2 намеренно отклоняется до вызова API. Успешную серию
   проверяют offline-тесты с подменой клиента либо явно разрешённый live-сценарий.

Обновлять страницу после изменений JS. URL скрипта дня 2 включает версию; старые
карточки на уже открытой странице не пересчитываются. Нужные результаты сначала
скачать, так как обновление страницы сбросит браузерную историю прогонов.

## Реальный smoke-тест дня 1

По запросу на реальную API-проверку, один вызов:

```sh
.venv/bin/pytest tests/test_day_01.py::test_day_01_live_openai --live-openai -s --tb=short
```

Настройки загружаются штатно без вывода `.env`: provider=openai, ключ и model ID,
доступный API-баланс. Тест временно включает `live` в своём процессе, файл не меняет.
Запущенный uvicorn не требуется. Используется настоящая модель и серверный HTML,
но не браузер. Лимит 512, timeout 30 секунд, автоматических повторов нет.

Успех: HTTP 200, непустой текст на странице, валидные debug JSON, status=completed,
фактическая модель. Выводятся модель и доступный usage. Нехватка настроек, ошибка API,
пустой/незавершённый ответ — не успешный пропуск. При ошибке не повторять вызов
автоматически; сохранить безопасную причину и сообщить ограничение проверки.

## Ручная приёмка второго дня с API

Это платные вызовы, не часть обычного pytest. Пользователь может выполнять их сам.
Уже завершённая серия и выводы находятся в [отчёте](results/week_01/day_02/README.md).
Повторение не требуется только ради подтверждения исторического статуса выполненного дня.
`AIAC_DAY_02_MODEL` позволяет выбрать совместимую модель только второго дня;
модель сохранённой серии deprecated, отключение объявлено на 2027-01-14.
Агенту перед новой серией нужно соотнести объём с запросом пользователя и бюджетом.
При стандартных настройках «все варианты» — до 15 запросов; 2–5 повторов позволяют
запустить до 10–25. Ошибки и остановка могут уменьшить фактическое число вызовов.

1. Убедиться по странице, что выбран ожидаемый провайдер/model ID. Не менять `.env`
   и не переключать модель молча. Один и тот же пример/схема используется для сравнения.
2. Выбрать сначала один вариант и 2 повтора (до двух вызовов). Проверить, что страница
   не перезагружается, прогресс меняется и двойное нажатие не создаёт вторую серию.
3. В карточках проверить текст, finish_reason, время и токены в **одной строке**:
   вход / выход / всего. Сверить их с usage в JSON ответа. При отсутствии usage —
   «нет данных»; не подставлять нули и не прибавлять reasoning-токены второй раз.
4. Проверить JSON запроса: вариант limit меняет max_completion_tokens;
   stop передаёт stop отдельным параметром; schema передаёт strict JSON Schema.
   Ввод двух символов `\n` преобразуется в реальный перенос, который в JSON снова
   виден как экранированная последовательность. Не обрезать готовый ответ локально.
5. Если stop возвращает HTTP 400 unsupported_parameter/param=stop, увидеть безопасную
   копию ошибки в «Ответ API». Остальные повторы этого варианта должны быть skipped,
   API-ошибка не должна увеличивать знаменатель числа ответов/JSON. Для закрытия
   требования нужен совместимый вариант модели, а не зелёные тесты обработки ошибки.
6. При совместимости параметров выполнить все варианты с повторами. Сопоставить
   raw-текст, результаты JSON-разбора и схемы: валидный JSON может не соответствовать
   схеме; пустой ответ, отказ и length не считать полноценным успешным завершением.
7. Если нужна проверка остановки, нажать её во время текущего вызова: дождаться его
   результата, убедиться в отсутствии следующего запроса и доступности экспорта.
   Разрывы сети/квоту безопаснее проверять автоматическими подменами.
8. Скачать JSON, проверить plan/config, model, endpoint, request/response, usage,
   секунды и статусы, наблюдения и отметки времени. Поля пользовательского вывода нет.
   Вывод с конкретными примерами оформить в документе дня отдельно.

`finish_reason=stop` может означать обычное окончание, а не срабатывание именно
пользовательского маркера. Ошибка API, отказ модели, неполный ответ, skipped и unknown —
разные исходы. При сетевом разрыве вызов мог состояться: неизвестный исход нельзя
автоматически повторять или выдавать за нулевой расход.

## Если среда мешает проверкам

- Есть предупреждение Starlette о deprecated httpx-интеграции, но проверки проходят.
  Не устанавливать httpx2 и не менять зависимости без согласования.
- Сетевой sandbox может блокировать OpenAI или localhost. Это ограничение среды,
  не доказательство неисправного ключа; использовать штатный механизм разрешений,
  не отключать защиты и не вводить fallback.
- Браузерный инструмент ранее был недоступен. Если так и осталось, указать это
  отдельно и попросить пользователя проверить UI; не выдавать JS-подмены за браузер.

После проверки в документ дня записать дату, команду/сценарий, фактическую модель,
параметры, число реально выполненных вызовов и исход. Для обычной регрессии явно
писать «без сети»; для реального сценария различать проверку агентом и подтверждение
пользователем. Зелёный pytest сам по себе не меняет статус задания на «выполнено».
