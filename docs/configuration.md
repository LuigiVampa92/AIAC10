# Локальная конфигурация: .env

`.env` в корне проекта задаёт настройки конкретного локального запуска, включая
секреты. Он не является кодом и не подключает новые API сам по себе.
`src/aiac/config.py` описывает настройки, которые приложение понимает.
`.env.example` — безопасный пример без ключей, который хранится в репозитории.

При первом запуске создать `.env` на основе `.env.example` и заполнить значения.
Если `.env` уже есть, менять только нужные строки, сохраняя остальные настройки.
Не копировать пример поверх действующего файла: это может затереть ключ.

## Что указывать

| Переменная | Назначение | Допустимые значения сейчас |
| --- | --- | --- |
| `AIAC_LLM_MODE` | Внутренний режим выполнения | `demo` — локальная заглушка без сети; `live` — реальный API |
| `AIAC_LLM_PROVIDER` | Сервис, к которому обращается приложение | Только `openai` (OpenAI) |
| `AIAC_LLM_MODEL` | Точный API ID модели выбранного провайдера | ID, доступный API-проекту пользователя |
| `AIAC_DAY_02_MODEL` | Необязательная отдельная модель только для эксперимента дня 2 | Пусто — использовать общую модель; для сохранённой серии: `gpt-4.1-mini-2025-04-14` |
| `OPENAI_API_KEY` | Секретный ключ OpenAI API-проекта | Собственный API-ключ; обязателен для `live` с `openai` |

Для реальной работы:

```dotenv
AIAC_LLM_MODE=live
# Поддерживаемые провайдеры: openai (OpenAI). Другие пока не подключены.
AIAC_LLM_PROVIDER=openai
AIAC_LLM_MODEL=gpt-6-luna
AIAC_DAY_02_MODEL=gpt-4.1-mini-2025-04-14
OPENAI_API_KEY=
```

Пустое значение ключа в примере нужно заменить своим локально. Значение модели —
пример, а не гарантия доступа: ID должен быть доступен именно вашему API-проекту.
При выборе другой модели OpenAI обычно достаточно изменить `AIAC_LLM_MODEL`,
но нужно проверить поддержку параметров конкретного задания.
Для дня 2 выбрана отдельная совместимая со stop и схемой модель через
`AIAC_DAY_02_MODEL`: она показывается на его странице и фиксируется в каждом запросе.
Это явное переопределение только дня 2, не скрытый fallback при ошибке. Без него
используется общая модель. Модель `gpt-4.1-mini-2025-04-14` deprecated и по текущей
официальной документации отключается 2027-01-14; после этого потребуется явно
выбрать доступную замену. Дни 1, 3–5 продолжают использовать общую настройку.
Ключ приложения не берётся из авторизации Codex, OpenCode или другого инструмента.

Режим и провайдер — разные настройки: `live` означает реальное обращение,
`openai` указывает адресата этого обращения. В `demo` ключ и модель не требуются,
API-клиент не создаётся. Неизвестный провайдер в `live` приводит к понятной ошибке,
а не к автоматическому переключению на OpenAI.

## Загрузка и приоритет

Настройки читает `Settings` из `src/aiac/config.py`. `.env` ищется в корне проекта,
а не в произвольной текущей папке запуска. Переменные окружения процесса
(в том числе Environment variables в PyCharm) имеют приоритет над `.env`.
Поэтому изменение файла не переопределит значение, оставленное в настройках IDE.
Для обычного запуска приоритет: окружение процесса → `.env` → значения по умолчанию.
Явные аргументы `Settings(...)`, используемые в тестах, выше окружения.

После изменений перезапустить сервер и проверить информационные режим/модель
на странице. Автоперезагрузка исходников не гарантирует применение изменений `.env`.
Не использовать устаревшие `AIAC_LLM_MODE=openai` и `AIAC_OPENAI_MODEL`:
актуальные значения — `live` и `AIAC_LLM_MODEL` соответственно.

Неизвестные переменные сейчас игнорируются (`extra="ignore"`). Опечатка в имени
не добавляет новую настройку и может оставить значение по умолчанию, поэтому
сверять имена с таблицей и `config.py`.

## Как добавить другого провайдера

Одной строки `AIAC_LLM_PROVIDER=...` недостаточно. Порядок расширения:

1. Согласовать провайдера, его API, модели, бюджет и новые зависимости при необходимости.
2. Добавить в `Settings` отдельное секретное поле ключа, например
   `anthropic_api_key: SecretStr | None`. Не заменять `OPENAI_API_KEY` общим ключом.
3. Реализовать адаптер в `src/aiac/llm/` и подключить его к выбору в `generate()`.
   Модули дней должны продолжать работать через общую границу.
4. Передавать адаптеру только его ключ. Проверять нужные ему настройки;
   отсутствие ключа неактивного провайдера не должно мешать работе активного.
5. Проверять поддержку лимитов, JSON Schema, stop, temperature и reasoning.
   Не игнорировать неподдерживаемые параметры и не делать скрытый fallback.
   Сохранить тайм-ауты, ограничение повторов и безопасные ошибки.
6. Добавить offline-тесты выбора адаптера, параметров, ошибок и изоляции ключей.
   Живой тест подключать отдельно, с явным включением и без автоматических повторов.
7. Обновить список провайдеров и пустые поля ключей в `.env.example`, эту инструкцию
   и архитектуру. По согласованию добавить локальный ключ в `.env` и переключить
   provider/model; реальный запрос выполнять только в разрешённом объёме.

Например, `ANTHROPIC_API_KEY` станет действующей настройкой только после реализации
соответствующего поля и адаптера. Сейчас поддержка Anthropic не реализована.

## Секреты и проверки

`.env` не публиковать и не включать в Git, логи или видео. В `.env.example` держать
только пустые ключи. Агент не читает и не выводит секреты; точечное изменение
реального `.env` выполняется только по прямому запросу пользователя с сохранением
остальных значений. Ключи не передавать в командной строке.

Обычный `.venv/bin/pytest` работает без API и расходов. Отдельная реальная проверка
первого дня описана в [README](../README.md#повторная-проверка-первого-дня): она
загружает локальные настройки штатным способом, но не выводит ключ.
