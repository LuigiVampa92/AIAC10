## Принятые пользователем решения

- Работа возможна в Codex, OpenCode и других системах. Основа создана в OpenCode.
- Один локальный FastAPI-сервер, общие Jinja2-шаблоны и CSS. Без SPA, БД и новых
  зависимостей без необходимости/согласования.
- Заголовок **«AI advent Challange №10»**, участник **«Павел Васильев»**.
  Сохранять выбранное написание. Блоки недель с темами, по пять кнопок дней на широком
  экране. Только «День N», без «Страница задания». Футера нет.
- На странице показывать оригинал условия; решения, статусы, приёмку и инструкции
  тестирования хранить в Markdown-документации. Не дублировать условие в HTML.
- Провайдер и модель показаны как информация, не редактируемые поля. Пояснения об
  оплате и внутренний demo не засоряют обычный интерфейс; тестовую заглушку нельзя
  выдавать за реальный ответ.
- Запуск без перезагрузки, видимое ожидание, защита от двойной отправки, раскрываемые
  JSON запроса/ответа. Без ключа и заголовков; ошибки — с безопасной диагностикой.
- В карточке дня 2 токены **в той же строке, что время**: вход / выход / всего.
  Нет usage — «нет данных», а не ноль. Ошибка API не считается ответом модели.
- Нет поля «Ваш вывод» в интерфейсе: выводы оформляются отдельно. JSON-экспорт
  содержит настройки, ответы, диагностику, метрики и автоматические наблюдения.
- Уменьшенный лимит дня 2 по умолчанию **64**, повторы **3**, диапазон **2–5**.
  Остальные варианты имеют защитный лимит 512. Число вызовов видно до запуска.

## Что переиспользовать и чего не предполагать

- `llm/client.py`: граница дня 1, Responses API, `ModelResult`. Usage есть в JSON
  ответа, но отдельных нормализованных полей времени/usage в этом результате нет.
- `llm/chat.py`: граница дня 2, Chat Completions, `ChatResult` с usage, временем,
  finish_reason, отказом и JSON. Не предполагает поддержку любого параметра моделью.
- `tasks/week_01/day_02.py`: план, валидация, варианты, один прогон. JSON Schema —
  ограниченное подмножество, не универсальная библиотека валидации.
- `tools/run_day_02.py`: повторение реальной серии по явному --live-openai,
  15 вызовов, либо 18 с контрольным limit=16. Требует новое имя файла, не перезаписывает
  архив; при API-ошибке останавливается без повтора. --model действует только на процесс.
- `tests/test_day_02_evidence.py`: проверка сохранённых доказательств без API.
  Проверяет архив, не доступность модели/баланса сейчас.
- `web/app.py`: общая навигация/формы и отдельные JSON endpoints дня 2. `registry`
  связывает дни с документами/модулями; POST дня 2 отдельно направляет в эксперимент.
- `web/templates/day_02.html`, `static/day_02.js`: последовательная серия в браузере,
  остановка после текущего вызова, частичный экспорт. При обновлении страницы история
  теряется; сервер не хранит серию. Никаких фоновых задач/БД сейчас нет.
- Скрипт дня 2 имеет URL с версией по mtime файла. После изменений обновить страницу;
  прежние карточки автоматически не перерисовываются. Поддержать это при доработках.
- Добавление дня 3 не должно автоматически переводить все дни на другой API или
  общий лимит. Общие компоненты выделять по реальному повторению.
