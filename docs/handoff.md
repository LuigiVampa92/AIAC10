# Передача контекста следующему агенту

Сверено с кодом и проверками 2026-11-08. Это краткая точка входа;
условия и подробные доказательства готовности остаются в документах дней.

## Как начать без восстановления чата

1. Прочитать `AGENTS.md`, проверить `git status --short` и относящийся к работе diff.
   Состояние Git не выводить из этой памятки; индекс и историю не менять.
2. Прочитать эту страницу, [архитектуру](architecture.md) и документ нужного дня.
3. Для разработки дня 3 открыть [его условие и предлагаемый план](tasks/week_01/day_03.md).
4. Проверки выполнять по [инструкции](testing.md). `.env` не читать и не переписывать
   ради получения контекста: конфигурация описана в [configuration.md](configuration.md).

Доказательства дня 2: [отчёт и исходные JSON](results/week_01/day_02/README.md).
Не смешивать функциональную готовность с пользовательскими commit/видео.

Реальные факты, которые нельзя потерять:

- Первоначальная ошибка `credit_balance_exhausted` устранена пользователем пополнением
  баланса. Не считать её текущим блокером и не просить снова добавить ключ.
- Пользователь показывал реальные результаты дня 2: baseline — completed с невалидным
  JSON; «Формат + лимит» — completed с валидным JSON и соответствием схеме.
  Это исторические отдельные наблюдения. Позже по прямому запросу пользователя
  агент закрыл полную серию: 15 основных + 3 контрольных + 1 probe = 19 реальных
  вызовов, 1578 токенов. Архив находится в `docs/results/week_01/day_02/`.
- Один диагностический реальный вызов агента подтвердил HTTP 400:
  `param=stop`, `code=unsupported_parameter`, сообщение
  `Unsupported parameter: 'stop' is not supported with this model.`
  Это был отказ API до генерации. Проблема решена **явной** настройкой
  `AIAC_DAY_02_MODEL=gpt-4.1-mini-2025-04-14` для дня 2, без изменения общей модели.
  На ней stop работает: 3/3 ответов с маркером `}` потеряли скобку и не разобрались
  как JSON. Формат/лимит 64/строгая схема — 3/3 валидных JSON и схемы каждый.
- На контрольном лимите 16 получено length в 3/3, но JSON всё ещё валиден. Не писать,
  что в этой серии лимит сломал синтаксис: проверка завершения независима от парсинга.
- `gpt-4.1-mini-2025-04-14` deprecated, объявленное отключение 2027-01-14
  (источник в отчёте). Это модель только дня 2 ради совместимости, **не модель дня 3**.
  Для новых повторений после отключения нужна явно выбранная совместимая замена,
  но историческое выполнение задания уже доказано архивом.
- В примере настроек используется `gpt-6-luna`; фактическую модель брать из настроек
  приложения/ответа API, не объявлять пример неизменным состоянием `.env`.
- Пользователь разрешил агенту диагностику и завершение реальной серии дня 2;
  эта серия уже выполнена, не нужно запускать её заново ради статуса.
  Полный бюджет новых массовых экспериментов не установлен. Для новой серии явно
  показать модель, объём и число вызовов; не превращать проверку UI в платный прогон.

## Принятые пользователем решения

- Работа возможна в Codex, OpenCode и других системах. Основа создана в OpenCode.
- Один локальный FastAPI-сервер, общие Jinja2-шаблоны и CSS. Без SPA, БД и новых
  зависимостей без необходимости/согласования.
- Заголовок **«AI advent Challange №10»**, участник **«Павел Васильев»**.
  Сохранять выбранное написание. Блоки недель с темами, по пять кнопок дней на широком
  экране. Только «День N», без «Страница задания». Футера нет.
- На странице показывать оригинал условия; решения, статусы, приёмку и инструкции
  тестирования хранить в Markdown-документации. Не дублировать условие в HTML.
- Провайдер и модель показаны как информация, не редактируемые поля. Пояснения об
  оплате и внутренний demo не засоряют обычный интерфейс; тестовую заглушку нельзя
  выдавать за реальный ответ.
- Запуск без перезагрузки, видимое ожидание, защита от двойной отправки, раскрываемые
  JSON запроса/ответа. Без ключа и заголовков; ошибки — с безопасной диагностикой.
- В карточке дня 2 токены **в той же строке, что время**: вход / выход / всего.
  Нет usage — «нет данных», а не ноль. Ошибка API не считается ответом модели.
- Нет поля «Ваш вывод» в интерфейсе: выводы оформляются отдельно. JSON-экспорт
  содержит настройки, ответы, диагностику, метрики и автоматические наблюдения.
- Уменьшенный лимит дня 2 по умолчанию **64**, повторы **3**, диапазон **2–5**.
  Остальные варианты имеют защитный лимит 512. Число вызовов видно до запуска.

## Что переиспользовать и чего не предполагать

- `llm/client.py`: граница дня 1, Responses API, `ModelResult`. Usage есть в JSON
  ответа, но отдельных нормализованных полей времени/usage в этом результате нет.
- `llm/chat.py`: граница дня 2, Chat Completions, `ChatResult` с usage, временем,
  finish_reason, отказом и JSON. Не предполагает поддержку любого параметра моделью.
- `tasks/week_01/day_02.py`: план, валидация, варианты, один прогон. JSON Schema —
  ограниченное подмножество, не универсальная библиотека валидации.
- `tools/run_day_02.py`: повторение реальной серии по явному --live-openai,
  15 вызовов, либо 18 с контрольным limit=16. Требует новое имя файла, не перезаписывает
  архив; при API-ошибке останавливается без повтора. --model действует только на процесс.
- `tests/test_day_02_evidence.py`: проверка сохранённых доказательств без API.
  Проверяет архив, не доступность модели/баланса сейчас.
- `web/app.py`: общая навигация/формы и отдельные JSON endpoints дня 2. `registry`
  связывает дни с документами/модулями; POST дня 2 отдельно направляет в эксперимент.
- `web/templates/day_02.html`, `static/day_02.js`: последовательная серия в браузере,
  остановка после текущего вызова, частичный экспорт. При обновлении страницы история
  теряется; сервер не хранит серию. Никаких фоновых задач/БД сейчас нет.
- Скрипт дня 2 имеет URL с версией по mtime файла. После изменений обновить страницу;
  прежние карточки автоматически не перерисовываются. Поддержать это при доработках.
- Добавление дня 3 не должно автоматически переводить все дни на другой API или
  общий лимит. Общие компоненты выделять по реальному повторению.

## Последняя контрольная точка

После закрытия дня 2, 2026-11-08: Ruff, format-check и mypy прошли; **87 Python-тестов passed,
1 live-тест skipped**, **7 JS-тестов passed**, синтаксис обоих JS проверен.
Live-тест дня 1 не повторялся. Реальные 19 вызовов дня 2 сохранены отдельно от
offline-проверок; в `.env` добавлена только отдельная модель дня 2, ключ/общая модель
сохранены. Есть предупреждение Starlette/httpx, оно
не ломает проверки и не является разрешением установить новую зависимость.

Визуальная проверка агентом ранее была недоступна: browser access host не работал,
обращение к Firefox завершилось тайм-аутом. Пользователь проверял UI самостоятельно.
Это ограничение прошлой среды, а не доказательство поломки приложения. При доступном
браузере проверить заново; не называть тесты на подмене DOM проверкой реального браузера.
