# Передача контекста — первые две недели завершены

**Дни 1–10 приняты пользователем. Прогресс 10 из 35.**
Недели 1–2 завершены, недели 3–7 (25 заданий) ожидают оригинальных условий.
Пользователь вернётся с заданиями третьей недели. Не придумывать их и не считать
технические заготовки выполненными. Git commit/push, публикация и видео — только
пользователь; их выполнение отдельно не подтверждено.

## Начало следующей сессии

1. Прочитать AGENTS.md, README.md, docs/challenge.md и docs/architecture.md.
2. Проверить git status/diff; сохранить существующие незакоммиченные изменения.
3. Получить и сохранить оригиналы новых условий в docs/tasks/week_03/day_YY.md,
   обновить страницы и статусы. Реализовывать по очереди после обсуждения требований.
4. Для предыдущей недели использовать [общий итог](weeks/week_02.md) и документы дней.
   Проверки и сценарии — docs/testing.md.

Новых зависимостей и платных API-прогонов не согласовано. Не читать реальные .env,
не переносить личные диалоги в публичную документацию и не использовать их для
стресс-прогонов без согласования. Все записи только внутри проекта; без git add/
commit/push и других изменений индекса/истории. Не запускать дополнительных агентов.
Авторизация инструмента разработки — не ключ приложения.

## Компоненты и память

- agents/simple.py — общий ограниченный агентный цикл и replay_input; верхнеуровневый
  status удаляется только из отправляемой копии (исправление HTTP 400 input[1].status).
- agents/tools.py — фиксированные USD=90 RUB/EUR=100 RUB, калькулятор только сложения,
  локальное время. Без часов в дне 6 модель даёт приблизительную UTC-метку,
  не показание часов. Инструменты в днях 8–10 не предоставляются.
- agents/storage.py — JsonHistory, необязательный state_type и Writer-протокол;
  атомарная запись tempfile/fsync/replace, fcntl-блокировка для macOS/Linux.
- agents/compression.py — SummaryConversation, граница сжатия и активный контекст.
  Summary обновляется по previous_summary + новому раннему фрагменту, не из эталонов.
- agents/strategies.py — только рабочая память: у Window/Facts history обрезается
  до N, журнал turns не читается для контекста. Facts — отдельный JSON со строками,
  обновляется до ответа после каждого пользовательского сообщения, включая recall.
- agents/branches.py — Workspace/Checkpoint/AttachedWriter; ветки и checkpoint
  сохраняются атомарно вместе. До 8 веток и 8 checkpoint, все копии глубокие.
- llm/reasoning.py и llm/tokens.py — общая граница генераций/подсчёта. Не дублировать
  HTTP-клиенты по заданиям. Профиль тарифов/окна известен только для точного gpt-6-luna.

Постоянные данные находятся в data/week_02/day_02 … day_05, каталог игнорируется Git.
У дней 9–10 comparison/conversation.json отделён от ручного диалога/веток.
Это личное состояние, не публикуемый архив результатов. Ключи приложения и HTTP-
заголовки не сериализуются. Новое пространство архивирует старое. Повреждённый JSON
не сбрасывается, неизвестный/ошибочный оплачиваемый запрос не повторяется автоматически.
После остановки сравнение продолжается только явной кнопкой, не при загрузке страницы.

## Лимиты и честность метрик

В днях 8–10 сообщение до 400000 символов, контекст до 12 млн, файл JSON до 16 МБ;
у дней 6–7 старые пределы 4000/60000. До 4096 выходных токенов, 30 с на API,
120 с на операцию. Summary/Facts — до 2048 выходных токенов.
Лимит $0.50 на ответ/ход с поддержкой и отдельно на всё сравнение дней 9–10.
Это стандартная расчётная защита, не полный биллинг: не включены индивидуальные
наценки и возможная цена API подсчёта. Подсчёты — сеть, но не генерации.
Неполные usage/цены — неизвестны, не ноль; reasoning уже входит в output.
Переполнение модели подтверждается кодом ошибки генерации, не локальным пределом,
бюджетом, ошибкой счётчика, тайм-аутом или rate limit.

Facts и summary не заменяются плохим/незавершённым результатом. Невалидный recall
JSON — «не оценено», не 0 деталей. Алиасы могут не узнать правильный синоним;
нужна ручная проверка спорной формулировки. Строки кода считаются по указанным
функциям без общей инфраструктуры. Один сценарий не даёт универсального рейтинга.
