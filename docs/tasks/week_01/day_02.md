## Оригинальное условие

🔥 День 2. Формат ответа

Отправьте один и тот же запрос, но:

- 👉 добавьте явное описание формата ответа
- 👉 ограничьте объём ответа (`max_tokens`)
- 👉 добавьте stop sequence
- 👉 задайте строгую схему ответа (JSON Schema / structured output)

Прогоните каждый вариант несколько раз.

Сравните ответы:

- 👉 без ограничений
- 👉 с ограничениями
- 👉 со строгой схемой
- 👉 проверьте, можно ли распарсить ответ кодом

Результат:
Один и тот же запрос с разным уровнем контроля + вывод, какой способ ломается и на чём

## Критерии приёмки

Критерии ниже выведены из оригинального условия:

- Один исходный запрос проверяется без дополнительных ограничений формата,
  с явным форматом в промпте, с лимитом вывода, со stop sequence и со строгой схемой.
- Каждый вариант повторяется несколько раз; количество повторов фиксируется.
- Для каждого ответа код проверяет возможность разбора; для структурированного
  результата дополнительно проверяется соответствие схеме.
- Сохраняются ответы, ошибки разбора и фактически отправленные параметры.
- Представлено сравнение уровней контроля с примерами сбоев и выводами.

## Решение и проверка

Доступна только общая техническая форма. Эксперименты не реализованы и не запускались;
результатов и выводов пока нет. Demo не выполняет условия задания.

Следующий шаг — согласовать запрос, схему, число повторов, модель и бюджет.
Перед реализацией проверить поддержку stop sequence и structured output выбранными
моделью и API. `max_tokens` сохранён в оригинале; фактическое имя параметра лимита
определяется API. Не имитировать поддержку stop обрезкой уже полученного ответа.
«Без ограничений» означает базовый вариант эксперимента; общие защитные лимиты остаются.
