## Критерии приёмки

Критерии ниже выведены из оригинального условия:

- Один исходный запрос проверяется без дополнительных ограничений формата,
  с явным форматом в промпте, с лимитом вывода, со stop sequence и со строгой схемой.
- Каждый вариант повторяется несколько раз; количество повторов фиксируется.
- Для каждого ответа код проверяет возможность разбора; для структурированного
  результата дополнительно проверяется соответствие схеме.
- Сохраняются ответы, ошибки разбора и фактически отправленные параметры.
- Представлено сравнение уровней контроля с примерами сбоев и выводами.

## Решение и проверка

Реализованы отдельная форма, планирование серии без API-вызовов и выполнение по одному
прогону за запрос. Браузер последовательно выполняет серию и обновляет результаты
без перезагрузки. Вся логика задания находится в `day_02.py`, вызов SDK — в
`src/aiac/llm/chat.py`. Первый день продолжает использовать Responses API.

Поля: исходный запрос (до 4000 символов), инструкция формата (до 2000), уменьшенный
лимит (16–512 токенов, по умолчанию 64), stop sequence (до 100 символов), JSON Schema (до 12000),
число повторов (2–5), выбор одного или всех вариантов. Есть редактируемый пример
извлечения имени, возраста и города. Провайдер и модель берутся из настроек.

| Вариант | Передаваемые ограничения |
| --- | --- |
| Базовый | Только исходный запрос, защитный лимит 512 токенов. |
| Формат в промпте | Исходный запрос + инструкция формата, лимит 512. |
| Формат + лимит | Та же инструкция, уменьшенный лимит из формы. |
| Формат + stop | Та же инструкция, stop из формы, лимит 512. |
| Строгая схема | Та же инструкция, response_format=json_schema, strict=true, лимит 512. |

Все варианты второго дня используют `/v1/chat/completions`: это позволяет
передавать настоящий `stop`, которого нет в текущем контракте Responses API.
Имя лимита в реальном запросе — `max_completion_tokens`; `max_tokens` сохранён
в оригинальном условии. Параметры конкретной модели проверяет API: нет скрытого
переключения модели/API, удаления параметра или обрезки ответа приложением.
Ссылки на официальные контракты:
[Chat Completions](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create),
[Responses](https://developers.openai.com/api/reference/python/resources/responses/methods/create).

При HTTP 400 вариант помечается ошибкой, оставшиеся его повторы пропускаются;
другие варианты продолжаются. Другие API-ошибки (включая сеть/квоту) останавливают
серию. При разрыве браузерного соединения текущий результат отмечается неизвестным,
автоматического повтора нет. Кнопка остановки завершает текущий вызов и сохраняет
его ответ, после чего прекращает серию. Тайм-аут одного API-вызова — 30 секунд,
автоматических повторов SDK нет. Настройки формы фиксируются на время серии;
если модель/провайдер на сервере изменились, следующий вызов отклоняется.

Поддерживается явно ограниченное подмножество JSON Schema: один `type` на узел,
типы object/array/string/integer/number/boolean/null, enum, properties, required,
additionalProperties=false и items. Корень — object, все поля объектов обязательны,
не более 30 полей объекта/значений enum, глубина до 8. Остальные ключевые слова,
включая $ref и внешние схемы, отклоняются до платных вызовов. Новых зависимостей нет.

Ответы проверяются как исходный JSON (без удаления Markdown или исправлений),
затем на соответствие схеме. Повторяющиеся ключи и нечисловые константы вроде NaN
отклоняются. Отдельно фиксируются отказ модели, неполный ответ, ошибка API,
пропущенный повтор и неизвестный исход. Успешный разбор сам по себе не означает
соответствие схеме или успешное завершение генерации.

На странице доступны сырые тексты, JSON тел API, фактическая модель, finish_reason,
usage и время каждого вызова. В карточке каждого прогона рядом со временем отдельно
показываются в той же строке входные, выходные и суммарные токены из usage; отсутствующие значения
обозначаются «нет данных», а не нулём. Сводка считает разобранные/соответствующие ответы,
ошибки, незавершённые ответы, пропуски и неизвестные исходы. Токены суммируются
только по ответам с известным usage; отсутствующие сведения не заменяются нулём.
`finish_reason=stop` не доказывает, что сработал именно пользовательский маркер.

Настройки, повторы, ответы, метрики и автоматические наблюдения скачиваются в JSON.
Пользовательский вывод формулируется вне интерфейса и фиксируется в документации
после экспериментов; отдельного поля ввода для него на странице нет.
Сервер не хранит историю, БД не добавлена. При обновлении
страницы результаты теряются; новый запуск заменяет их после успешной проверки
нового плана. Ключи, HTTP-заголовки и сырые исключения в отчёт не включаются.

### Корректировки и диагностика stop

Уменьшенный лимит по умолчанию повышен до 64 выходных токенов. Подсказка про `\n`
уточнена: это два вводимых символа, преобразуемых в реальный перевод строки перед
API-вызовом. В JSON-панели реальный перевод строки также показывается экранированно,
как требует синтаксис JSON.

После сообщения пользователя выполнен один минимальный реальный запрос с `stop`.
API настроенной модели вернул HTTP 400:
`param=stop`, `code=unsupported_parameter`, `type=invalid_request_error`,
`message="Unsupported parameter: 'stop' is not supported with this model."`.
Это несовместимость параметра с моделью, а не повреждение JSON сгенерированного ответа.
Модель и `.env` автоматически не менялись. Полноценный stop-эксперимент пока не завершён:
для него потребуется явно выбрать совместимую модель.

В ошибочных прогонах теперь сохраняется и отображается безопасная копия ответа API:
HTTP-статус и поля error.message/type/param/code. Сообщение об unsupported stop
указывает конкретный параметр. Заголовки и трассировки не включаются, значение
локального ключа и распознаваемые API/Bearer-токены маскируются. Если HTTP-ответа
нет (например, при разрыве соединения), тело ответа не выдумывается.
Диагностический JSON ошибки не считается ответом модели при подсчёте метрик.

После изменений прошли 82 Python-теста (1 opt-in live-тест пропущен), 6 JS-сценариев,
Ruff, format-check, mypy и проверка синтаксиса JS. Добавлены проверки безопасной
диагностики stop, маскирования секретов, преобразования `\n`, исключения ошибок
из числа ответов модели и экспорта без поля пользовательского вывода.

URL скрипта второго дня содержит версию по времени изменения файла, чтобы после
обновления страницы браузер загружал новый JS вместо закэшированной старой версии.
Карточки уже завершённых серий не перерисовываются автоматически при обновлении кода.
