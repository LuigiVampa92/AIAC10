## Решение и проверка

Реализован интерактивный эксперимент на /weeks/1/days/4.
Пользователь согласовал предложение и уточнил число повторов: **1–10**, по умолчанию 5.
Для точного сценария оригинального условия выбрать оба запроса, все температуры и 5 повторов.
Это 30 вызовов; максимум при 10 повторах — 60. Минимальная выбранная серия — один вызов.

Два фиксированных запроса:

- Покупка со скидками, округлением и доставкой из дня 3 v2; эталон 4494.
  В дне 4 используется фиксированный собственный текст, без привязки к будущим изменениям дня 3.
  Формат: JSON только с двумя строковыми полями answer (цифры без единиц)
  и непустым explanation. Оценивается answer; верное объяснение не исправляет ошибочное поле.
- Генерация пяти названий приложения для домашних растений. Только JSON с массивом names;
  пять разных названий, каждое — два русских слова через один пробел,
  без знаков препинания и цифр. Проверка регистра не учитывает; ё и е не объединяются.
  Соответствие теме и творческое качество оценивает пользователь, не LLM-судья.

Общая модель не меняется: **gpt-6-luna** задана явно только для дня 4.
Responses API, reasoning.effort=none — фиксированное условие, переключателя reasoning нет.
Меняется только temperature=0 / 0.7 / 1.2; промпт каждого типа одинаков во всех повторах,
без истории и передачи ответов предыдущих вызовов. top_p/seed не задаются.
Лимиты: 1024 выходных токена, 60 секунд, автоматических повторов нет, store=false.
Формат задаётся только промптом: строгая схема/JSON mode API не включены.
Поддержка temperature при none проверена 2026-11-09 по
[официальной документации](https://developers.openai.com/api/docs/guides/latest-model).
Агент реальную совместимость в текущем аккаунте не проверял: при отказе API серия
останавливается без скрытого удаления temperature, переключения модели или fallback.

Серия последовательна. Можно выбрать один тип запроса и одну температуру.
Показаны число будущих вызовов, прогресс, защита от двойного запуска и остановка
после текущего вызова. Ошибка API или неизвестный сетевой исход останавливает серию.
Предыдущие результаты остаются доступны при ошибке проверки нового плана.
Результаты только в памяти страницы, без архива и экспорта; обновление/новая серия их заменяет.

Для каждой комбинации показаны карточки повторов рядом (с переносом на узком экране)
и строка таблицы: обработано/план, число ответов, верных итогов, неверных итогов
при соблюдённом формате, нарушений формата, неполных/отказов, API-ошибок и неизвестных
исходов, уникальные тексты и итоги/наборы, разные названия, вход/выход/всего токенов
и суммарное время вызовов. Незавершённые ответы не получают оценку формата/правильности.
Сырые тексты сравниваются посимвольно; итог покупки — поле answer среди ответов
правильного формата. Наборы названий нормализуются по регистру и сортируются:
перестановка списка не создаёт нового набора. Разнообразие названий считается
только среди валидных списков и не является автоматической оценкой качества.
Неизвестный usage не заменяется нулём; reasoning не прибавляется повторно.

Для temperature=0 показываются наблюдения о совпадении текстов. Один ответ
не даёт основания судить о повторяемости; частичные серии явно оговариваются.
Даже все совпадения не гарантируют детерминизм будущих вызовов.
