## Решение и проверка

### Выбор моделей

При открытии страницы браузер вызывает GET /weeks/1/days/5/models. Сервер
загружает список через OpenAI models.list(), включая страницы ответа,
отбирает текстовые семейства по ID и возвращает их ID и отдельно известные тарифы. Ключ остаётся
в LLM-границе. Загрузка списка не вызывает генерацию и происходит автоматически при открытии страницы.
Кнопки обновления нет; при ошибке для повторной загрузки обновить страницу.
Выбор моделей всегда виден перед отдельным спойлером задач и эталонов.
По умолчанию предложены gpt-6-luna / gpt-6.1-sol / gpt-6-astra для маленькой,
средней и флагманской ролей. Можно искать ID вводом в поле и выбрать другую
модель, в том числе старого поколения. Три ID должны различаться.
Если предложенный ID отсутствует в списке, он не заменяется молча: нужен выбор
доступной модели. Ошибка каталога не подменяется статическим списком.

models.list не сообщает цены, поддержку Responses API, текстовой модальности
или reasoning. В списке оставлены текстовые семейства GPT, o1/o3/o4, chatgpt и gpt-oss,
включая снимки и fine-tune ID. По имени исключены audio/realtime, изображения,
транскрибация/TTS, embeddings, moderation, search и video. Неизвестные семейства
скрываются консервативно. Это фильтр по ID: API каталога не предоставляет
метаданные модальности; новые семейства потребуют обновления фильтра.
Совместимость оставшихся моделей с Responses и reasoning проверяет реальный API.
Неподходящая модель даёт безопасную ошибку, без fallback, скрытого удаления
параметров и автоматического повтора. Произвольная API-совместимость всех ID
не обещается. Источник: [List models](https://developers.openai.com/api/reference/resources/models/methods/list).

Настроек reasoning в интерфейсе нет. Сервер автоматически использует low для
семейств GPT-5/GPT-6/o1/o3/o4 (кроме o1-mini); старым и неизвестным семействам
параметр не отправляется. Это политика по ID, не автоматическое определение
возможностей через models.list. Модель, не поддерживающая low, даст ошибку без
повтора с другими параметрами. Для неизвестного reasoning-ID отсутствие параметра
означает серверное значение по умолчанию, а не доказанное отключение рассуждения.
Фактически применённая настройка отражается в плане, итоговой таблице и запросах.
Пользователь не может переопределить effort через JSON маршрута. Температура не задаётся.

### Серия и оценка

Пять задач и эталоны переиспользуются из дня 3 v2, в плане фиксируется версия.
Один и тот же текст задачи, JSON answer и краткое explanation для всех моделей;
оценивается строковое поле answer по правилам дня 3. Промпт не содержит эталон.
Повторы 1–10, по умолчанию один: 15 вызовов, максимум 150.
Каждый вызов независим; модели чередуются по задачам в фиксированном порядке ролей.
Остаточное влияние порядка и нагрузки API на скорость не исключено.
Лимит 16000 выходных токенов, 120 секунд, без повторов, store=false,
Responses API, service_tier=default (Standard). Настройки других дней не меняются.
При API-ошибке или неизвестном сетевом исходе серия останавливается целиком.
Можно остановить после текущего вызова. Частичные карточки остаются видимыми.

Итоговая таблица: верно/план, обработано, среднее время ответа, вход/выход/всего
токенов, расчётная стоимость USD, число неполных/отказов/ошибок. Среднее время
только по полученным ответам, включая неполные; не по API-ошибкам. Время включает
API-операцию, не является чистым временем генерации. Под каждой задачей карточки
трёх моделей с повторами, фактическим model ID, ответом, JSON и тарифами.

Отношение расходов и разница точности в процентных пунктах выводятся только
после полной серии маленькой и флагманской без незавершённых/ошибочных ответов.
Неправильный завершённый ответ остаётся в знаменателе. При неизвестной стоимости
или нулевой базе отношение неприменимо. Отдельно перечислены задачи, которые
маленькая модель решила во всех запланированных повторах. Это наблюдения на
данном наборе, не универсальное доказательство достаточности маленькой модели.

[GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini).

Справочник локальный, цены не скачиваются в реальном времени. У пользователя
нет полей ввода ставок, источника и даты. Тариф выбирается сервером по точному ID;
в плане и каждом результате фиксируются применённые ставки, источник и дата.
Для неизвестного ID, fine-tune или непроверенного снимка — «нет данных»;
не подставлять цену похожего ID и не считать ответ бесплатным. Изменение цены
провайдера требует обновления справочника по официальному источнику. Это задача
сопровождения приложения, а не действие пользователя перед каждой серией.
Клиент передаёт только ID: ручные ставки в JSON запрещены контрактом.

Расчёт: (input−cached) × ставка входа + cached × ставка кэша + output × ставка
выхода, с делением на миллион. Reasoning входит в output, второй раз не добавляется.
Отсутствующий cached count, usage, ставка или неподдерживаемая метрика cache-write
дают неизвестную стоимость, не ноль. Используется тариф выбранного ID, фактический
ID из ответа также сохраняется. Расчёт не заменяет биллинг и не включает налоги,
кредиты аккаунта и нестандартные надбавки. Предполагаются короткие входы этих пяти задач.

До запуска показываются число вызовов и стоимость выходных токенов при достижении
лимита всеми ответами плюс оговорка о входе; это предел по выбранным ставкам,
не прогноз фактического расхода. При неизвестных тарифах предел не вычисляется.
Результаты только в памяти страницы до обновления или новой серии, без экспорта/архива.
