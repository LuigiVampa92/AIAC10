Критерии ниже выведены из оригинального условия:

## Решение и проверка

Страница /weeks/2/days/3 содержит только ручной сохраняемый диалог и таблицу
роста расходов по ходам. Инструментов, автоматических сценариев и поля настройки
бюджета нет. Обработчик /probe и генераторы синтетических историй удалены.

Диалог хранится отдельно в data/week_02/day_03/conversation.json с прежними
атомарной записью, блокировкой, архивированием и восстановлением после перезапуска.
История дня 7 не читается и не меняется. Неуспешный/прерванный ход не повторяется
автоматически; новый диалог архивирует прежний. Ключи и заголовки не сериализуются.

### Подсчёт и представление

Общая граница llm/tokens.py использует responses.input_tokens.count из установленного
SDK без новых зависимостей, с тайм-аутом 30 с и без повторов. Это сетевые обращения,
но не генерации. Перед ответом отдельно считаются:
- новое сообщение пользователя, включая оформление;
- прежняя история (0 для пустой);
- полный вход с общими инструкциями и всей историей.

Для пустой истории — 2 подсчёта, для непустой — 3. Изолированные значения не обязаны
складываться в полный вход из-за оформления сообщений и общих инструкций.
[Метод подсчёта](https://developers.openai.com/api/docs/guides/token-counting).
При ошибке счётчика генерация не отправляется, fallback на оценку по символам нет.

Ответ и расход за ход — input/output/total_tokens из фактического usage API.
Reasoning уже входит в output и не прибавляется второй раз. Таблица показывает
размер нового сообщения, истории, полного входа, usage хода и накопленные токены/
стоимость. Накопленный расход повторных запросов — не размер текущего контекста.
Неизвестные метрики не становятся нулём; известная часть стоимости показана отдельно.
Подробности хода содержат модель, время, генерации/подсчёты и безопасные ошибки.
Время цикла включает измерительные сетевые обращения.

SimpleAgent получает необязательный before_call, max_prompt_chars и
max_context_chars. День 8 передаёт пустой набор функций; инструменты, tool_choice
и parallel_tool_calls не отправляются в payload. Инструкции — обычный собеседник.
Дни 6–7 сохраняют прежнее поведение без дополнительных подсчётов.

### Пределы и расходы

Сообщение: до 400000 символов (100× относительно 4000 в днях 6–7).
Технический предел полного контекста — 12 млн символов, файла истории — 16 МБ.
История не обрезается и не сжимается. truncation=disabled; превышение окна
в ручном диалоге отправляется модели, если хватает расчётного лимита расходов.
Ответ ограничен 4096 токенами, API — 30 с, весь ход — 120 с.

Проверенный профиль точного ID gpt-6-luna: окно 1050000 токенов;
стандартные USD/1M: input 0.10, cached 0.01, cache write 0.125, output 0.50.
При входе >272000 ставки входа/кэша ×2, выхода ×1.5.
[Источник](https://developers.openai.com/api/docs/models/gpt-6-luna), проверен 2026-11-15.
Другим ID лимиты и тарифы не угадываются: без тарифа генерация блокируется.
После ответа стоимость оценивается по usage с учётом кэша; при неполных данных
остаётся неизвестной. Региональные/договорные наценки и возможная цена endpoint
подсчёта не включены. Оценка не является фактическим счётом провайдера.

**Фиксированный лимит: $0.50 на один ответ**, константа MAX_COST_USD в модуле дня.
Параметра бюджета нет ни в UI, ни в JSON-вводе API: попытка max_cost_usd отвергается
валидацией. На странице оставлена информационная плашка.
Перед генерацией сравнивается стоимость всего входа по максимальной ставке
input/cache write плюс резерв полного ответа, с long-context множителями.
Если оценка больше 50 центов, генерация не отправляется; в ошибке видны обе суммы.
Можно уменьшить текст или начать новый диалог. Это не баланс и не общий бюджет
разговора; деньги заранее не списываются, короткий ответ может стоить меньше.

### Переполнение проверяется вручную

Короткий разговор: несколько небольших сообщений. Длинный: продолжить тот же
диалог и/или вставлять большие фрагменты текста, сравнивая строки таблицы.
Чтобы проверить переполнение, наращивать историю сверх окна и смотреть ответ API.
Личный диалог дня 7 для этого не используется.

Только ошибка генерации с кодом context_length_exceeded/context_window_exceeded
фиксируется как model_context_overflow. Ошибка счётчика — count_api_error,
нехватка лимита расходов — cost_guard. Тайм-аут, rate limit, технический предел
или иной отказ не считаются подтверждением переполнения. При отсутствии usage
расход неизвестен, не ноль. Повторов и скрытой смены модели нет.
