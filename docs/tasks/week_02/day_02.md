## Критерии приёмки

Критерии ниже выведены из оригинального условия:

- История messages хранится постоянно в JSON или SQLite, а не только в памяти процесса.
- Сохраняются сообщения диалога, вызовы инструментов и результаты этих вызовов.
- При новом запуске агент загружает сохранённую историю и продолжает диалог с ней.
- Проверен сценарий с инструментом до перезапуска и вопросом о прошлом контексте после него.
- Перезапуск приложения не уничтожает сохранённые сообщения и результаты инструментов.

## Решение и проверка

На /weeks/2/days/2 — постоянный диалог с агентом дня 6 и теми же тремя
инструментами. Сообщения, ответы, вызовы функций и результаты автоматически
загружаются при открытии страницы. Рядом с каждым ответом показаны модель,
статус, время, число API-обращений и токены. Аргументы и результаты инструментов
раскрываются отдельно; полная сохранённая история также доступна на странице.
Выбор инструментов оформлен крупными плашками и восстанавливается из файла.

Формат хранения — JSON, без новых зависимостей и БД.
Файл: data/week_02/day_02/conversation.json.
Он содержит version, id, model (настроенный ID), status, tools, history и turns.
history хранит всю последовательность сообщений и исходных output items,
включая reasoning/encrypted_content, function_call и function_call_output с call_id.
turns — представление ходов для интерфейса с фактической моделью и метриками.
Непрозрачные reasoning-данные не декодируются; ключи и HTTP-заголовки в файл не пишутся.

JsonHistory в src/aiac/agents/storage.py выполняет атомарную запись через
временный файл в том же каталоге, flush/fsync и os.replace. Файл создаётся
с правами 0600. Каталог data/ уже исключён из Git.
Блокировка fcntl предотвращает одновременную запись двумя запросами/процессами
(реализация для macOS/Linux). Проверяется граница проекта; нельзя писать через
символические ссылки вне проекта или заменять файлы-ссылки.

SimpleAgent.run принимает предыдущую history и callback сохранения.
Контрольная точка пишется перед API-обращением, после получения output items,
после выполнения функции и по завершении хода. Перед следующим запросом
replay_input удаляет status только из отправляемой копии; исходные записи
остаются в истории. Выбор function_call по-прежнему делает модель.
Управление контекстом следует [OpenAI Docs](https://developers.openai.com/api/docs/guides/conversation-state).

Маршруты:
- GET /weeks/2/days/2/history — локальная загрузка без вызова модели.
- POST /weeks/2/days/2/run — следующий ход с восстановленной полной историей.
- POST /weeks/2/days/2/new — новый диалог; предыдущий сохраняется как
  archive-<id>.json в том же каталоге, без удаления его истории.

Один активный диалог общий для локального приложения, не отдельный на каждую
вкладку/пользователя. Архивы сохраняются на диске; переключение между ними
в интерфейсе не реализовано. Ключ/заголовки приложения не сериализуются.
Просмотр истории и новый диалог работают без сети; отправка требует live,
провайдера openai, выбранной модели и отдельного API-ключа.

### Ошибки и ограничения

Если приложение остановилось посреди вызова, последний ход остаётся running.
Он виден после перезапуска, но автоматически не повторяется: исход оплаченного
API-запроса мог остаться неизвестным. Ошибка API/отказ/incomplete/timeout также
сохраняются и блокируют следующий ход. Можно начать новый диалог, сохранив старый
в архиве. Это восстановление истории, не автоматическое возобновление прерванной операции.

Повреждённый JSON или неизвестная версия не заменяются пустой историей.
При ошибке диска новый запрос останавливается. Изменение настроенного ID модели
требует нового диалога, без скрытой замены модели. При сетевой ошибке браузер
не повторяет POST и предлагает обновить страницу для чтения фактического состояния.
Непосланный текст сохраняется в форме. Ошибки конфигурации/demo не создают ход.

Сохранены лимиты дня 6: 4000 символов сообщения, 60000 символов полного контекста,
6 API/5 функций на ход, 4096 выходных токенов/30 с на API, 120 с на цикл.
Файл ограничен 16 МБ. История не сжимается и не обрезается: при достижении лимита
нужен новый диалог. Стратегии управления контекстом относятся к дням 9–10.
Публичное многопользовательское размещение и Windows в этой реализации не проверены.

### Сценарий повторной пользовательской проверки

1. Открыть /weeks/2/days/2. Отправить: «Меня зовут Павел. Конвертируй
   25 USD в рубли и запомни результат». Проверить реальный fixed_exchange,
   его результат 2250.00 RUB и ответ агента.
2. Остановить сервер Ctrl+C. Запустить снова из корня:
   .venv/bin/python -m uvicorn aiac.web.app:app --reload --host 127.0.0.1
3. Обновить страницу. Убедиться, что видны прошлые сообщения и результат функции.
4. Спросить: «Как меня зовут и сколько рублей получилось в прошлый раз?
   Не делай повторную конвертацию». Проверить ответ по сохранённым данным
   и отсутствие нового вызова конвертера в ходе.
5. При необходимости начать новый диалог: текущая история должна попасть
   в локальный архив, а новая форма — начать независимую беседу.
