## Принятые решения и важные нюансы

### Инструменты и агентный цикл

Инструменты находятся в Python-коде и выполняются локально: конвертер с фиксированными
USD=90 RUB / EUR=100 RUB, калькулятор только со сложением и локальные часы.
В API отправляются схемы функций; модель выбирает действие и аргументы.
Один запрос пользователя может вызвать несколько обращений к API: локальное
исполнение функции не устраняет сетевые обращения для управления шагами.
Инструменты не гарантируют экономию времени/токенов, но дают внешние данные
и проверяемое вычисление. При выключенных часах в дне 6 модель даёт приблизительную
метку в том же формате UTC, это не показание часов. Курсы учебные, не текущие.

Наблюдение пользователя для раннего варианта дня 6 на gpt-6-luna:
все функции — 5 API / 4 локальных вызова, 3533 токена, 7.064 с;
без функций — 1 API / 0 локальных вызовов, 482 токена, 3.753 с.
Это одна пара до последних правок промпта, не новый прогон финального кода.
В сводке принятого интерфейса оцениваются валидность JSON и ресурсы,
не сумма и не точность временной метки.

### История, контекст и токены

Полный архив и контекст модели — разные сущности. Размер текущего контекста
не равен накопленному расходу: старая история отправляется и учитывается повторно.
Вход измеряется через `responses.input_tokens.count`, ответы и расход — по usage.
Изолированные запрос/история включают оформление сообщений, поэтому их числа
не обязаны складываться в полный вход с общими инструкциями. Сетевые подсчёты
показаны отдельно от генераций; reasoning не прибавляется к output повторно.
Неизвестный usage/тариф остаётся неизвестным, а не нулевым.

День 8 намеренно оставлен только ручным: нет инструментов, автосценариев,
кнопок short/long/overflow и маршрута `/probe`. До 400000 символов на сообщение,
контекст до 12 млн символов, автоматическая обрезка API выключена.
Только код ошибки контекста от генерации подтверждает реальное переполнение.
Локальный предел, бюджет, ошибка счётчика, тайм-аут и rate limit — другие исходы.

Расчётная защита расходов фиксирована на $0.50: за ответ в дне 8,
за ход с поддержкой памяти в днях 9–10 и отдельно за всё сравнение каждого дня.
Она не настраивается в интерфейсе или JSON. Оценка учитывает полный вход и резерв
максимального ответа, но не является полным биллингом: договорные/региональные
наценки и возможная цена endpoint подсчёта не включены. Проверенный профиль
в `llm/tokens.py` есть только для точного ID gpt-6-luna; остальные не угадываются.

### Summary, Facts и Window

Согласованы значения по умолчанию: последние 6 сообщений и порог сжатия 10 новых.
Сообщения — user/assistant, 6 сообщений — 3 пары. У Summary между обновлениями
хвост растёт; ничего не выбрасывается до сжатия. Обновление использует прежний
summary и только новый ранний фрагмент. Архив остаётся полным.

Window/Facts держат в рабочей history только хвост; журнал ходов нужен для просмотра
и не возвращает модели забытое. Facts хранится отдельно и обновляется моделью
после каждого сообщения пользователя, включая вопрос проверки. Неправильный JSON
не заменяет принятую память. У Summary также не принимаются неуспешные сводки.
Стоимость создания/обновления памяти считается вместе с последующими ответами:
сокращение входа не обязательно означает экономию суммарного расхода.

### Сравнение и ветвление

[Сценарий summary-memory-v1](../scenarios/week_02/day_04.json) подготовлен заранее:
12 пользовательских сообщений, общий реальный разговор из 24 сообщений,
8 проверяемых деталей, включая изменение бюджета. Он переиспользуется в днях 9–10.
Эталонные ответы не передаются модели. Воспроизведение одинакового исходного
разговора позволяет сравнить память, не смешивая его с разными ответами ассистента.

День 9: до 15 генераций. День 10: обычно 30 при настройках 6/10, до 39 при частом
summary. Общие 12 ответов создаются один раз; у Facts/summary учитываются все
поддерживающие вызовы, в том числе обновление Facts перед recall.
Невалидный JSON — «не оценено», необычный правильный синоним можно проверить вручную.
Строки кода считаются по указанным функциям без общей инфраструктуры; это локальная
мера объёма реализации. Рекомендации по стратегиям не являются универсальным рейтингом.

Checkpoint включает сообщения, память и настройки. Ветки A/B — глубокие копии
одного снимка; изменения не затрагивают соседнюю ветку и исходный checkpoint.
Смена стратегии создаёт новую ветку из доступного хвоста без импорта прежних
Facts/Summary и без скрытого восстановления забытых сообщений. Старую ветку сохраняем.
До 8 веток и 8 checkpoint; новое пространство архивирует предыдущее целиком.

## Где хранится состояние

| День | Постоянные данные |
| --- | --- |
| 6 | Нет серверной истории между запусками; результаты страницы временные. |
| 7 | `data/week_02/day_02/conversation.json` |
| 8 | `data/week_02/day_03/conversation.json` |
| 9 | `data/week_02/day_04/conversation.json` и `comparison/conversation.json` внутри этого каталога |
| 10 | `data/week_02/day_05/conversation.json` с ветками/checkpoint и отдельный `comparison/conversation.json` |

`data/` исключён из Git. Это личное состояние приложения, не публикуемый отчёт.
Истории и снимки предыдущих дней не используются для новых экспериментов без согласования.
JSON пишется атомарно через временный файл/fsync/replace; блокировка fcntl рассчитана
на macOS/Linux. Ключ API приложения и HTTP-заголовки не сериализуются.
После сбоя running/unknown не повторяется автоматически: оплаченный запрос мог
выполниться. Новый диалог/эксперимент архивирует прежний. Повреждённый JSON не сбрасывается.
Сохранение работает между запусками, но это не автоматическое возобновление прерванной операции.

## Проверки и границы подтверждения

Все пять заданий приняты пользователем. Последняя проверка кода:
Ruff check/format-check и mypy прошли, **213 Python passed / 1 live skipped**,
**55 JS passed**. Команды и сценарии — в [docs/testing.md](../testing.md).

Агент не выполнял платные API-прогоны второй недели и не подтвердил визуальную
проверку браузером. Offline-тесты подменяют API, проверяя настоящую локальную
логику, сериализацию, измерения, бюджеты, ошибки и независимость веток.
Численные результаты реальных сравнений дней 8–10 отдельно не переданы:
не выдумывать экономию, число сохранённых деталей или подтверждённое переполнение.
Приёмка пользователем и доступная эмпирическая запись фиксируются отдельно.
Новый публикуемый архив реальных результатов второй недели не создавался.

При подготовке этого итога менялась только документация; новых прогонов не было.
