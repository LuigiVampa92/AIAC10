## Наблюдения и выводы

- Базовый: JSON 0/3, схема соблюдена 0/3.
- Формат в промпте: JSON 3/3, схема соблюдена 3/3.
- Формат + лимит: JSON 3/3, схема соблюдена 3/3.
- Формат + stop: JSON 0/3, схема соблюдена 0/3.
- Строгая схема: JSON 3/3, схема соблюдена 3/3.

Формат, схема и завершение проверяются отдельно.
finish_reason=stop не доказывает срабатывание маркера.

## Примеры ответов

### Базовый

```
Имя: Анна
Возраст: 28 лет

```

```
{"name": "Анна", "age": 28, "city": "Казань"}
```

```
{"name":"Анна","age":28,"city":"Казань"
```

### Строгая схема

```
{"name":"Анна","age":28,"city":"Казань"}
```

## Ограничения

Отчёт — снимок серии. Частичная серия не считается полной.
Нет данных — не нулевой расход.
Исходные JSON нужны для проверки вызовов.


## Вывод после просмотра агентом

В новом прогоне повторилась основная картина: свободный ответ не разбирается как JSON,
инструкция формата и строгая схема дали 3/3 валидных объектов. Stop-маркер «}»
удалил необходимую закрывающую скобку, поэтому 0/3 ответов разобраны. Лимит 64
не испортил JSON в этой серии; утверждать, что любой малый лимит обязательно ломает
формат, нельзя. Контрольные stop/limit=16 из старого архива не запускались повторно.
