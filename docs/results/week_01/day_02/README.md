# День 2: реальные эксперименты и вывод

**Результат: требования второго дня выполнены.** Серия проведена агентом 2026-11-08
через тот же модуль `day_02.execute()`, который обслуживает Web-интерфейс.
Это реальные API-ответы, а не подмена SDK. UI ранее проверен пользователем;
автоматический запуск ниже является CLI-проверкой, не браузерным E2E.

## Данные и условия

- Провайдер: OpenAI, endpoint `/v1/chat/completions`.
- Запрошенная и фактически возвращённая модель: `gpt-4.1-mini-2025-04-14`.
- Один и тот же исходный запрос: «Извлеки имя, возраст и город из текста:
  Анна, 28 лет, живёт в Казани.»
- Инструкция формата: «Верни только JSON-объект с полями name (строка), age
  (целое число), city (строка). Без пояснений, Markdown и дополнительных полей.»
- Схема: объект с обязательными name:string, age:integer, city:string,
  additionalProperties=false. Полный JSON схемы сохранён в плане серии.
- Пять вариантов × три повтора = **15 основных вызовов**. Дополнительно —
  **3 заранее объявленных контрольных вызова с лимитом 16** и **1 проверка stop**.
- Лимит основного limit-варианта — 64; остальных — 512. Stop-маркер — `}`.
  Строгая схема передаётся через response_format/json_schema/strict=true.
- Temperature, seed и reasoning не задавались; скрытых повторов, ремонта JSON,
  переключения API/модели и локального обрезания текста не было.
- Timeout 30 секунд на вызов, max_retries=0. Текст разбирался строго и проверялся
  на соответствие схеме. Метрики ошибок API и JSON-разбора учитывались раздельно.

Архив:

- [experiment.json](experiment.json) — все 18 основных/контрольных ответов,
  планы, фактические тела запросов и ответов, usage, время и оценки.
- [compatibility_probe.json](compatibility_probe.json) — дополнительная проверка
  stop: запрос требовал `OKEND`, stop=`END`, фактический ответ — `OK`.

## Сравнение

Счётчики JSON/схемы относятся ко всем трём ответам варианта. «Завершено» —
нормальное завершение по протоколу API; оно само по себе не гарантирует корректный JSON.
Токены и время — суммы трёх вызовов; время включает клиентскую API-операцию.

| Вариант | Завершено | JSON разобран | По схеме | Входные токены | Выходные токены | Всего | Время, с |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Базовый | 3/3 | 0/3 | 0/3 | 96 | 51 | 147 | 3.622 |
| Формат в промпте | 3/3 | 3/3 | 3/3 | 207 | 48 | 255 | 3.506 |
| Формат + лимит 64 | 3/3 | 3/3 | 3/3 | 207 | 48 | 255 | 2.375 |
| Формат + stop `}` | 3/3 | 0/3 | 0/3 | 207 | 53 | 260 | 2.436 |
| Строгая схема | 3/3 | 3/3 | 3/3 | 339 | 48 | 387 | 2.524 |
| Контроль: формат + лимит 16 | 0/3 (length) | 3/3 | 3/3 | 207 | 48 | 255 | 2.576 |

В 18 вызовах не было ошибок API или отказов модели. Они израсходовали 1559 токенов
(1263 входных + 296 выходных); сумма времени — 17.039 с. Вместе с отдельной проверкой
stop выполнено **19 вызовов, 1578 токенов**. Это usage API, не расчёт денежного счёта.

## Примеры и интерпретация

Базовый ответ первого повтора:

```text
Имя: Анна
Возраст: 28 лет
Город: Казань
```

Информация полезна человеку, но `json.loads` такой текст не разбирает. Так произошло
во всех трёх базовых повторах: отсутствие формата — первая обнаруженная причина сбоя.

С инструкцией формата и со строгой схемой получен, например:

```json
{"name":"Анна","age":28,"city":"Казань"}
```

Все три повтора каждого из этих вариантов соответствовали схеме. Для этого простого
запроса одной инструкции оказалось достаточно, но три успешных повтора не являются
гарантией будущего поведения. Строгая схема задаёт структуру на уровне API; она
добавила входные токены и не освобождает от обработки отказа или ограничения вывода.

С `stop=["}"]` первый ответ:

```text
{"name":"Анна","age":28,"city":"Казань"
```

API исключил маркер остановки, поэтому закрывающей скобки нет. Все три ответа
невалидны как JSON. Здесь генерация действительно выполнилась, а параметр был
принят: это отличается от прежнего HTTP 400 на глобальной модели. Само значение
finish_reason=stop без дополнительного контекста не доказывает срабатывание маркера;
вывод подтверждается также текстами и отдельным контрольным запросом `OKEND`.

Лимит 64 в этой серии не вызвал обрезания: каждый ответ занимал 16 выходных токенов.
В контрольной серии с лимитом 16 API вернул length во всех трёх повторах, однако
сохранившийся текст ещё был валидным JSON и соответствовал схеме. Это пограничный
случай: **проверка парсинга и проверка завершения генерации необходимы независимо**.
Не подменять наблюдение утверждением, что в этой серии лимит испортил JSON:
наблюдалось ограничение генерации, но не синтаксическая порча.

В варианте limit=64 встречается city со значением «Казани», а не «Казань». Оба значения
прошли структурную схему (строка). Это показывает границу проверки: JSON Schema
контролирует форму и типы, а не семантическую нормализацию названия города.

## Итоговый вывод

Без описания формата программный разбор сломался на свободном тексте. Инструкция
формата помогла во всех трёх проверках этой задачи; строгая схема также дала 3/3
валидных объектов, с дополнительным расходом входных токенов. Неправильно выбранный
stop-маркер сломал JSON детерминированным удалением значимой скобки. Лимит нужно
выбирать с запасом: пограничный length нельзя считать полноценным завершением,
даже если текущий текст уже разобрался. Поддержку параметра моделью, завершение API,
синтаксис JSON, соответствие схеме и смысл ответа нужно оценивать раздельно.

Это вывод по одному запросу и трём повторам, а не рейтинг моделей и не доказательство
гарантированной воспроизводимости. Дополнительные вызовы ради подбора желаемого
исхода не выполнялись.

## Повторение

Команда этой серии (18 платных вызовов; probe отдельно):

```sh
.venv/bin/python tools/run_day_02.py --live-openai --model gpt-4.1-mini-2025-04-14 --include-limit-stress --output docs/results/week_01/day_02/experiment.json
```

Существующий файл защищён от перезаписи: для нового запуска выбрать **новое имя**.
Без --include-limit-stress будет 15 вызовов; без --live-openai программа откажется
запускаться. Файл обновляется после каждого результата, при API-ошибке серия
останавливается без повтора. --model применяется только к этому процессу.

Проверка уже сохранённых доказательств без API:

```sh
.venv/bin/pytest tests/test_day_02_evidence.py
```

Эти тесты сверяют матрицу, сырые ответы, метрики, оценки и наблюдения. Они проверяют
архив, а не текущую доступность API/баланса.

Для дня 2 добавлена настройка `AIAC_DAY_02_MODEL`, не меняющая `AIAC_LLM_MODEL`
других дней. Модель эксперимента выбрана ради проверенной поддержки stop и схемы,
а не как рекомендация для новых задач. Она deprecated, объявленное отключение —
**14 января 2027**: [официальный список OpenAI](https://developers.openai.com/api/docs/deprecations).
Для повторения после этой даты понадобится явно выбрать совместимую доступную модель;
сохранённые доказательства остаются историческими результатами выполненного задания.
