# AIAC

Лаборатория челленджа: **7 недель × 5 дней**. Код создаётся AI-агентами.
Основа проекта набросана в OpenCode. Дальнейшая работа возможна в **Codex,
OpenCode и других системах**: проект не привязан к одному инструменту разработки.

Подготовлены 35 страниц-заготовок и общая интеграция с моделями. Получены условия
всех пяти дней первой недели — «Основы LLM»: первый API-запрос, формат ответа,
способы рассуждения, температура и версии моделей.
[Список заданий и статусы](docs/challenge.md#полученные-задания).
День 1 выполнен: успешный реальный запрос в Web подтверждён пользователем.
Commit и видео пока не зафиксированы. Дни 2–5 ожидают реализации,
недели 2–7 — условий.

## Быстрый вход в контекст для агента

1. Прочитать [AGENTS.md](AGENTS.md): границы работы и разрешения едины для всех систем.
2. Проверить `git status --short` и относящийся к задаче diff, сохранив существующие изменения.
3. Прочитать [описание челленджа](docs/challenge.md),
   [архитектуру](docs/architecture.md) и документ нужного дня.
4. Изучить модуль дня, затрагиваемые общие компоненты и тесты.

Оригиналы условий и актуальные статусы хранятся в документах дней.
День 1 функционально завершён; далее переходим к неделе 1, дню 2, затем дням 3–5.
При передаче работы другому агенту обновлять там результат, выполненные проверки,
ограничения и следующий шаг, чтобы продолжение не зависело от истории чата.

## Быстрый старт

Python 3.12 и uv. Если uv отсутствует, установить его локально, без глобальных изменений:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install uv
```

```sh
UV_CACHE_DIR=.cache/uv UV_PYTHON_DOWNLOADS=never .venv/bin/uv sync --inexact --frozen
.venv/bin/python -m uvicorn aiac.web.app:app --reload --host 127.0.0.1
```

Открыть http://127.0.0.1:8000. Активация venv не обязательна.
`--inexact` сохраняет локальный bootstrap uv, зависимости приложения закреплены в uv.lock.
В чистом окружении с глобальным uv можно использовать `uv sync --frozen`.

## Модели и оплата

По умолчанию работает **demo**, без API и расходов. Настройки читаются из окружения
или `.env` в корне. Пример — `.env.example`, настоящий `.env` в Git не попадает.
Назначение всех переменных, приоритет настроек и порядок подключения новых
провайдеров описаны в [инструкции по .env](docs/configuration.md).

Реальный режим: `AIAC_LLM_MODE=live`, `AIAC_LLM_PROVIDER=openai`, отдельный
`OPENAI_API_KEY`, доступный API-аккаунту `AIAC_LLM_MODEL`.
Режим и выбор провайдера разделены; сейчас реализован только провайдер OpenAI.
Другой provider возвращает понятную ошибку, без fallback и передачи ключа OpenAI.
Подписка или авторизация инструмента разработки не является API-ключом приложения.
**ChatGPT Plus не оплачивает OpenAI API.**
Агенты включают платный режим и выполняют живые проверки только в рамках
явного разрешения пользователя. Обычные проверки не требуют ключа и баланса.
Сервер только локальный; не публиковать без дополнительных мер защиты.

## Проверки

```sh
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/mypy src
.venv/bin/pytest
```

По умолчанию тесты не используют реальный API: клиент подменяется, сеть блокируется,
а живая проверка пропускается. Пропущенный live-тест не подтверждает доступность API.

### Повторная проверка первого дня

Проверить серверный сценарий без расходов:

```sh
.venv/bin/pytest tests/test_day_01.py -m "not live_openai"
```

По явному запросу пользователя агент может проверить реальный API и отображение
ответа на странице. Команда выполняет **один платный запрос** с текущей моделью
из локальных настроек, лимитом 512 выходных токенов, тайм-аутом 30 секунд и без повторов:

```sh
.venv/bin/pytest tests/test_day_01.py::test_day_01_live_openai --live-openai -s --tb=short
```

Нужны `OPENAI_API_KEY`, `AIAC_LLM_MODEL`, `AIAC_LLM_PROVIDER=openai` и доступный API-баланс.
Тест сам включает `live` только для своего процесса, не изменяя `.env`.
Конфигурация загружается штатно; ключ не выводится и не передаётся в командной строке.
Запуск сервера отдельно не нужен: используется FastAPI TestClient, который вызывает
реальный API и проверяет серверный HTML. Браузерные JS, индикатор ожидания и внешний
вид этот тест не проверяет.

Проверяются непустой ответ, статус `completed`, JSON запроса/ответа и фактическая
модель. Фиксированный текст ответа не требуется. При успехе печатаются модель,
параметр лимита и доступный usage; ошибки, demo и пустой/незавершённый ответ
не считаются успехом. Отсутствие ключа/модели при явном live-запуске — ошибка,
а не успешный пропуск.

Для запроса агенту достаточно: «Проверь день 1 без сети» или
«Выполни один реальный API-тест дня 1». Агент фиксирует дату, команду, результат,
модель и ограничения в документе дня. Не перезапускает платный тест автоматически
при ошибке и не объявляет реальную проверку успешной по результатам подмены клиента.

## Навигация

- [Правила агентов](AGENTS.md), [условия](docs/challenge.md), [архитектура](docs/architecture.md).
- `docs/tasks/week_XX/day_YY.md` — условие и статус дня, источник описания в браузере.
- `src/aiac/tasks/week_XX/day_YY.py` — реализация дня.
- `src/aiac/web/`, `src/aiac/llm/` — общая оболочка и интеграция моделей.
- `demo/checklist.md` — памятка для записи видео.

На страницах заданий отображается оригинальное условие; технические отчёты
и инструкции по проверке доступны в Markdown-документах дней.
Конфигурация и расширение провайдеров описаны в `docs/architecture.md`.
После миграции старые `AIAC_LLM_MODE=openai` и `AIAC_OPENAI_MODEL` больше не используются:
заменить их на `live` и `AIAC_LLM_MODEL`. Если переменные заданы в конфигурации запуска
IDE, обновить их там тоже: окружение процесса имеет приоритет над `.env`.
После изменения настроек перезапустить сервер.

Индекс, commit, push, remote и теги пользователь контролирует самостоятельно.
Фактическое состояние Git проверяется перед работой, а не выводится из этого описания.

`opencode.jsonc` относится только к OpenCode и не требуется для запуска приложения.
Он не настраивает разрешения Codex или других систем. При смене инструмента
правила проекта сохраняются; настройки доступа конкретной системы проверяются отдельно.
Проект не меняет глобальные настройки и выбранную пользователем модель разработки.
